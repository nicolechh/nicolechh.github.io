Color

Every color is a CSS custom property on :root, redefined for dark mode (both by prefers-color-scheme and by [data-theme] for a manual override). Never hardcode a hex value in new markup — reach for one of these.

--tag-blueFixed (not theme-swapped) — see below

--tag-blue is deliberately fixed, not swapped per theme like --select is. White text on #2E5BEA passes WCAG AA (~5.5:1) in both themes; --select's dark-mode value (#7391FF) is a light tint meant to sit on a dark page, not carry white text itself. Any new component that fills a shape solid blue with white text on top should use --tag-blue, not --select — check contrast again if you introduce a new color/text pairing like this.

Spacing & layout

Few hard numbers — most spacing is a clamp() so it scales with viewport rather than jumping at breakpoints.

  • --gutter — 24px desktop, 0 ≤560px. Reserves room for the ruler frame; collapses to 0 once the ruler's hidden so margins stay symmetric on mobile.
  • --maxw — 1180px. Caps main's width; content padding is clamp(20px, 4vw, 56px) inside that.
  • --step — 8px base unit, used sparingly for small fixed gaps.
  • Section rhythm is clamp-based throughout — e.g. clamp(80px, 12vh, 120px) bottom padding on #work. Match the existing clamp ranges in a section rather than inventing a fixed px gap for a new one.

Breakpoints

  • 901px+ — work grid goes 3-column with subgrid row alignment across cards
  • ≤900px — work grid and about-body drop to 1 column
  • ≤560px — "mobile": hero name stacks & centers, ruler/gutter hidden, lede centers
  • ≤500px — nav collapses straight to the hamburger (deliberately the same threshold centered nav would start crowding the toggle — no in-between state)

Components

Marquee (selection box)

Selected content
The core "design-tool selection" motif — .sel-box/.tbox. Solid 1–1.5px --select border, four corner-handle squares. Used on the hero name, the lede, and card hover/focus states. Always solid, never dashed — that changed early on and stuck.

Tag / filled marquee

New tag

Same corner-handle idea, but with a solid --tag-blue fill and bold white text instead of a transparent frame — this is .sticker, the "Product designer" tag's class. Border color matches the fill exactly (so it's structurally still a marquee, even though the border itself is invisible against the same-color fill). Always --tag-blue for a filled marquee, never --select — see the color contrast note above.

Motion toggle

Reduce motion
Visually a small 26×14 pill, but .motion-track's real hit target is 44×44 (negative margin pulls the layout footprint back to the pill's size). Only the switch is clickable — the label is connected for accessible naming via aria-labelledby, not by wrapping it in the control, so clicking the text does nothing. This pattern — small visual, generous hit area, click scoped to the control only — is the template for any future toggle/switch.

Chrome & signature motifs

The "design tool" identity — dot grid, ruler, custom cursor. These are canvas/JS-driven on the real page (see index.html's script), so what's below is a static swatch of the same tokens, not a live demo. Open the homepage to see them move.

Dot grid

26px pitch, --dot resting / --dot-hot near a real (non-touch) pointer. Reacts only while a touch is actually held down — never on scroll or an idle finger.

Ruler

--chrome glass + blur, --edge ticks, --accent cursor marker (mouse only, never for touch — a touch jumps rather than glides, so the marker would just be noise). Hidden entirely ≤560px.

Custom cursor

A Figma-style arrowhead (--tag-blue fill, white outline) with live coordinates, replacing the OS cursor — but only on (hover:hover) and (pointer:fine) devices. Touchscreens never get cursor:none or the chip at all.

Rules for adding a new page or section

A full worked example of a new page built on this system: any case study page — long-form article layout (case-study.css) plus the shared nav bar (nav.js) on top of these same tokens, no dot-grid/cursor chrome. See DESIGN-SYSTEM.md's "Case study pages" section.

  • Link styles.css — don't paste or fork any of it into a new page's own <style>.
  • Colors, spacing, radii: reach for a token above. If nothing fits, that's a sign the system needs a new token — add it to :root (and its dark overrides) rather than hardcoding a one-off value in a selector.
  • Any new solid-fill-plus-text-on-top color pairing needs its own contrast check in both themes, the way --tag-blue was — don't assume an existing token carries over.
  • Hover styles go behind @media (hover:hover); press/tap feedback uses :active; keyboard focus uses :focus-visible (or :has(:focus-visible) for a parent) — never :focus-within, which a touch tap triggers too.
  • Any custom control (toggle, button) needs a hit target of at least 24×24 (WCAG 2.5.8), ideally 44×44 (2.5.5) — expand the hit area with margin/padding rather than growing the visual control, the way .motion-track does.
  • Respect prefers-reduced-motion / the site's own reduce-motion toggle ([data-motion="reduced"]) for any new animation or transition.
  • New marquee-style chrome reuses .sel-box's pattern (border + 4 handles); a new filled tag reuses .sticker's. Don't invent a third variant of the same idea.
  • Check both themes and at least the 375px / 900px / 1200px widths before calling a new section done.
  • Update this page and DESIGN-SYSTEM.md if the new work introduces a genuinely new token or component — not for a one-off use of existing ones.
