Guardrail: A System for Designers & Developers

Reduced developers’ custom styling by 90% and gave designers the foundation to expand the product.

The Problem

Mode

The audit found three problems that looked separate:

  • Color: accumulated with no guidelines governing usage
  • Mode: the severity chip (1) passed AA in both modes, but the alert notice (2) and outlined button (3) failed in dark
  • Iconography: icons came from different libraries at mixed sizes

All three came from decisions made per screen, not from a shared system. The fix had to serve two groups: responders triaging dense security data, and the designers and developers building a consistent product.

Constraints

  • The system was built alongside the redesign
  • The system had to be legible to code, not just to designers
  • What I built had to work for colleagues immediately
  • Tables couldn’t lose density, they hold info a responder triages

The Decisions

1 — A palette was the start, not the answer

Working with Guardrail’s front-end developer, I layered semantic tokens on top of the palette. Each token is defined by five things: where it’s used, its intent, how much attention it draws, how it’s applied, and its state.

For example, component / secondary / high / background / default is the default background for a CTA in the secondary brand color, weighted to draw the eye first.

Designers wanted a quick color; developers needed each token to mean the same thing everywhere. I chose consistency over speed, so the system is slower to learn but much harder to misuse. Light and dark became one more axis of the taxonomy, and every value passes at least AA.

2 — Two views, not one

Responders needed every column of data; designers needed to build tables without starting over each time. I built a template from reusable components, putting critical information first, so dense rows stay scannable.

On smaller screens, I kept the table and added a list view for legibility. Breakpoints decide the default: table only above 768px, and a table/list toggle below that, defaulting to table from 640–768px and to list below 640px.

Ship & Collaboration

Guardrail’s front-end developer and I named the tokens together, so design and code shared one vocabulary and engineering could stop checking values. The system, redesign, and new features shipped before the acquisition.

The Outcome

The flagged components now pass AAA in both modes, and every other component passes at least AA. Over the next year, our design team used the system to create new features, with developers writing around 90% less custom styling. Post-acquisition, it evolved into the next step of Rain’s design system.

Reflection

Building on Shipfaster UI meant most of the three weeks went into re-tokenizing components one variable at a time. Next time I’d do fewer up front, letting later screens decide what else was needed. The taxonomy’s weight was the risk I watched: if designers had reached for raw palette values, my fallback was a short list of everyday tokens, with the full path saved for edge cases.
